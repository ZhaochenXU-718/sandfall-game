# 排行榜公平性备忘

记录日期：2026-08-29

状态：暂缓实现；不影响当前 MVP 和本地最高分

## 1. 当前结论

当前屏幕自适应只改变棋盘和 HUD 的显示尺寸与位置，不改变游戏规则、棋盘数据或计分公式。因此，不同屏幕尺寸仍使用相同的：

- `12 × 20` 宏观棋盘；
- `108 × 180` 沙粒网格；
- 60 Hz 固定物理 tick；
- 软降、硬降、消除和连锁计分规则。

进阶模式与经典休闲模式不共用本地最高分；经典休闲的颜色数量和速度组合也分别记录。未来线上排行榜只应比较完全相同的模式与规则配置。

在相同规则版本、随机种子和按 tick 输入序列下，核心模拟应产生相同棋盘状态和分数。屏幕尺寸本身目前不会直接造成分数差异。

## 2. 暂缓处理的公平性风险

以下问题不阻塞当前试玩版，但上线跨玩家排行榜前必须重新评估：

### 2.1 触控尺度

横向拖动、点击容差和硬降距离目前使用固定 UI 点数。响应式布局下，棋盘单格显示尺寸会随设备变化，因此不同屏幕的相对操作灵敏度可能略有差异。

后续建议将距离阈值换算为“宏观格尺寸”或棋盘归一化坐标，并保持长按时间等时间阈值一致。

### 2.2 低性能设备的时间优势

核心模拟使用固定时间步长，但当单帧补算超过上限时会丢弃积压时间。游戏显示时间由模拟 tick 推导，因此持续掉帧的设备可能表现为现实时间中的慢动作，给予玩家更多反应时间。

后续建议记录每局累计丢失时间；竞技模式可提高补算策略的公平性，或在丢失时间超过阈值时禁止成绩进入排行榜。

### 2.3 随机序列不同

普通模式当前以开始时间生成随机种子，不同玩家会遇到不同的方块、颜色和沙粒坍塌序列。这不属于屏幕适配问题，但会影响严格的横向排名。

后续可采用每日或赛季共享种子，或按挑战种子建立独立榜单。每条成绩都应保存种子和规则版本。

### 2.4 输入方式差异

桌面键盘、手机触控及未来可能加入的虚拟按键具有不同操作效率。若排行榜同时覆盖多个输入平台，应评估合榜是否合理，必要时按模式或平台分榜。

### 2.5 客户端成绩可信度

客户端本地分数可以被修改，不能直接作为有奖励或竞争性的排行榜成绩。正式上线时应提交规则版本、随机种子和输入回放，由服务端校验或重新模拟。

## 3. 重新启动该工作的条件

出现以下任一需求时，恢复排行榜公平性设计：

- 开始开发跨玩家在线排行榜；
- 开始开发每日挑战、赛季或奖励型竞赛；
- Web、微信和抖音平台需要合并排名；
- 排名成绩关联现金、虚拟道具或其他实际奖励。

## 4. 后续实施清单

1. 固定竞技模式的规则版本和配置快照。
2. 将触控距离统一换算为棋盘格或归一化坐标。
3. 定义共享种子、榜单周期和输入平台分类规则。
4. 记录掉帧丢失时间，并确定成绩有效阈值。
5. 保存按 tick 输入回放，确保相同输入可以确定性复现。
6. 由服务端验证成绩、规则版本、种子和回放结果。
7. 覆盖不同屏幕、30/60/120 Hz 刷新率和性能降级设备的公平性测试。

## 5. 当前范围决定

当前阶段不修改游戏核心、屏幕适配、触控阈值或固定步长策略，继续使用 Web 本地最高分。该备忘只保留风险和后续入口，不将排行榜纳入当前 MVP。
