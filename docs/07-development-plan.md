# 开发计划

以下为单人或小团队的 MVP 计划。时间为粗略估算，应在完成技术验证后重新评估。

## M0：技术验证（2～3 天）

目标：确认核心模拟和动态纹理在目标设备可行。

- 创建 Cocos 2D TypeScript 工程。
- 实现 `168 × 288` TypedArray 棋盘。
- 实现简单沙粒下落。
- 将棋盘上传为一张动态纹理。
- 在 Web 和至少一台中低端手机上测量性能。

退出条件：满棋盘模拟和渲染仍满足性能预算。

## M1：纯核心玩法（3～5 天）

- 带种子的 PRNG。
- 方块定义、移动、旋转、碰撞和锁定。
- 方块沙化。
- 稳定 4 tick 判定。
- 八方向连通扫描。
- 整分量同步删除。
- 坍塌和连锁。
- 出生碰撞与游戏结束。
- 核心单元测试和确定性回放测试。

退出条件：无 UI 也能通过自动输入完整运行一局。

## M2：首个可玩 Web 版（3～5 天）

- 首页、游戏页、暂停和结算页。
- 动态沙粒渲染与活动块渲染。
- 手机手势与桌面键盘。
- 分数、存活时间、下一块和危险提示。
- 基础音效、震动接口和本地最高分。
- 新手引导。

退出条件：目标用户无需口头解释即可完成首次消除。

## M3：微信小游戏（2～4 天）

- 微信构建配置和真机调试。
- 安全区域与胶囊按钮适配。
- 生命周期、本地存储和分享适配。
- 包体与启动时间优化。
- 平台审核材料和隐私检查。

退出条件：微信真机完整游玩 20 分钟无阻断问题。

## M4：抖音小游戏（2～4 天）

- 抖音构建配置和真机调试。
- `tt` 平台服务实现。
- 安全区域、生命周期、存储和分享适配。
- 包体、音频与弱网测试。
- 平台审核材料。

退出条件：核心规则与 Web/微信结果一致，平台功能可降级。

## M5：打磨与小规模测试（1～2 周）

- 调整颜色、速度、锁定延迟、计分和随机袋。
- 优化消除预兆、连锁反馈、音效和手感。
- 接入基础埋点。
- 收集首局消除率、单局时长和重开率。
- 修复高频崩溃、卡顿和误触问题。

退出条件：达到内部设定的留存和稳定性门槛，再决定排行榜、广告或原生 App。

## MVP 优先级

### P0

- 完整核心循环
- 确定性模拟
- 手机触控
- 游戏结束与重开
- 本地最高分
- Web/微信/抖音构建

### P1

- 新手引导
- 音效和震动
- 分享结果图
- 性能档位
- 基础埋点

### P2

- 平台排行榜
- 每日种子
- 激励广告
- 皮肤
- 原生 App

## 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 沙粒更新方向产生偏置 | 堆积手感不自然 | 交替扫描方向并使用确定性随机 |
| 触控手势误触旋转 | 操作挫败 | 手势状态机、阈值测试、虚拟按钮备选 |
| 消除难以形成 | 首局失败过快 | 八方向连通、颜色袋、预览和数值测试 |
| 连锁反馈遮挡棋盘 | 可读性下降 | 特效分层、强度上限、可关闭震动 |
| 小游戏包体或启动过慢 | 用户流失/无法上传 | 首包精简、Asset Bundle、真机追踪 |
| 平台 API 差异污染逻辑 | 多端维护成本高 | 强制平台服务接口和依赖规则 |
