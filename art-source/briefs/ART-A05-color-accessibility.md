# ART-A05：核心色彩与可读性规范

状态：已完成视觉定调，等待后续 UI 批次统一实装与微信、抖音真机复核。

视觉方向：C「霓虹像素沙」。

测试参考：[ART-A05 色彩与可读性测试板](../concepts/art-a05-color-accessibility-board.png)

适用基准：Cocos 设计宽度 `360`，棋盘背景 `#111827`，微信与抖音小游戏。

## 1. 本次结论

现有前四种沙粒颜色保持不变。第五色由偏蓝的紫色 `#A66CFF` 调整为紫红色 `#C257B7`，避免在红绿色觉差异模拟中与蓝色过度接近。

未选中描边由 `#375373` 调整为 `#4E7398`。旧描边在主面板上的对比度约为 `2.36:1`；新描边约为 `3.77:1`，超过重要非文字 UI 的 `3:1` 检查目标。

其他文字、背景、危险和高亮颜色不需要修改。

沙粒颜色顺序保持不变，只替换 Color ID 5 的 RGB 值，避免影响随机袋、存档、连通判断和玩法配置。

## 3. 背景、面板与边界

| 用途 | 色值 | 说明 |
|---|---|---|
| 画布背景 | `#050D19` | 页面最深背景 |
| 棋盘背景 | `#111827` | 动态沙粒底色，不使用渐变 |
| 主面板 | `#0C121F` | HUD、弹窗与主要容器 |
| 次级面板 | `#091728` | 模式设置和内层容器 |
| 闲置描边 | `#4E7398` | 重要可操作面板和按钮的最低描边色 |
| 装饰暗线 | `#375373` | 只可用于分隔线、不可操作装饰和背景纹理 |
| 遮罩背景 | `#03070F`，约 80% | 暂停与 Game Over 背景遮罩 |

规则：

- `#375373` 不再承担“这里可以点击”或“当前控件边界”的信息。
- 1 px 细线抗锯齿后会显得更淡；重要边界优先使用 `1.5～2 px` 和 `#4E7398`。
- 棋盘内部不增加亮边框，避免边框被误认为可消除沙粒。

## 4. UI 强调、奖励与危险

| 用途 | 色值 | 使用约束 |
|---|---|---|
| 青色选中态 | `#41CDC3` | 选中框、次按钮、焦点线 |
| 蓝色交互 | `#5B8DEF` | 普通功能按钮和信息强调 |
| 金色 CTA | `#FFC44B` | 首页开始、确认、升级奖励 |
| 金色按钮文字 | `#101827` | 仅置于金色实心按钮上，对比度 `11.21:1` |
| 强奖励文字 | `#FFD66B` | 连锁、升级、大额加分 |
| 危险红 | `#FF636B` | 危险高度、失败、不可逆警告 |

危险、选中与禁用状态不得只通过颜色传达：

- 危险状态同时使用顶部位置、警告符号或短促呼吸动画。
- 选中模式同时使用描边、顶部短线或勾选符号。
- 禁用状态同时降低不透明度并取消辉光/按压反馈。
- 消除闪光继续使用被消除沙粒自身颜色；中心允许升亮，但不漂白成纯白。

## 5. 文字可读性

| 文字角色 | 色值 | 主面板对比度 | 结论 |
|---|---|---:|---|
| 主文字 | `#EEF3FF` | `16.85:1` | 通过 |
| 次文字 | `#B4C2DB` | `10.41:1` | 通过 |
| 弱提示 | `#6F8EB1` | `5.51:1` | 通过，仍需遵守最小 12 号字 |
| 危险文字 | `#FF636B` | `6.46:1` | 通过 |
| 强奖励文字 | `#FFD66B` | `13.44:1` | 通过 |

本项目使用 WCAG 2.2 作为保守检查基线：常规小文字目标不低于 `4.5:1`，重要非文字控件与图形目标不低于 `3:1`。这不是在宣称小游戏已经完成完整无障碍认证。

参考：

- WCAG 2.2 文本对比度：<https://www.w3.org/TR/WCAG22/#contrast-minimum>
- WCAG 2.2 非文字对比度：<https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast>
- WCAG 2.2 不仅依赖颜色：<https://www.w3.org/WAI/WCAG22/Understanding/use-of-color>

## 6. 色觉差异检查

测试板包含正常视觉、红色弱/缺失方向、绿色弱/缺失方向和蓝黄色觉差异方向的近似模拟。模拟采用 Machado、Oliveira 与 Fernandes 的生理模型矩阵作为生产期检查工具：

- 论文：<https://doi.org/10.1109/TVCG.2009.113>
- 说明：模拟只能发现高风险配色，不能替代真实玩家测试，也不能保证每位玩家的感知一致。

结论：

- 原第五色 `#A66CFF` 在绿色觉差异模拟中与星海蓝接近，改为 `#C257B7` 后差距明显增加。
- 五种颜色在四组预览中都保留了不同的色相或明度位置，没有出现完全重合的颜色对。
- 金砂黄和海盐青亮度最高，星海蓝和霓虹紫红较暗；这种亮度层级可辅助色相判断。
- 玩家只需要判断沙粒是否同色，不需要记忆颜色名称；仍需在后续无口头试玩中验证第五色加入后的识别速度。

## 7. 低亮度与动态效果

- 测试板提供约 35% 线性亮度预览，用于发现暗部吞没，不等同于具体手机面板的物理测量。
- 弱提示文字不得低于 `#6F8EB1`，装饰文字可以更暗但不能承载规则。
- 蓝色和紫红色的颗粒纹理强度不得高于当前 `0.18`；继续加深会让最暗颗粒接近背景。
- 暗色面板上禁止使用低透明度彩色正文。
- 真机验收时分别测试系统亮度约 25%、50% 和 100%，并在普通室内光与强环境光下各观察一次。
- 连锁闪光需要耀眼但不能整屏泛白；高连锁时优先增加彩色光晕范围、粒子和持续时间，不无限提高峰值亮度。

## 8. 后续实装映射

正式 UI 批次需要完成以下替换：

1. `DEFAULT_SAND_PALETTE[5]`：`#A66CFF` → `#C257B7`。
2. 重要未选中面板/按钮描边：统一使用 `#4E7398`。
3. `#375373` 保留为纯装饰暗线，不用于交互边界。
4. 将色值集中为主题常量，避免 `SandfallGameComponent.ts` 继续散布相近但不一致的 RGB。
5. 微信和抖音各完成一次 2 色、4 色和 5 色真机局，重点观察蓝色与紫红色相邻时是否能快速识别。

批次 A 只确定规范，不在本项直接修改运行时代码；颜色替换将在首页与游戏内 UI 实装批次统一完成，避免概念规范和现有占位界面混合一半。

## 9. 验收标准

- 所有常规小文字对其实际背景达到 `4.5:1`。
- 重要按钮、面板边界和状态指示达到 `3:1`。
- 所有沙粒的最暗纹理相对棋盘背景达到 `3:1`。
- 正常、三种色觉差异预览和低亮度预览中没有完全重合的颜色对。
- 危险、选中、禁用和连锁信息均具有颜色以外的第二视觉线索。
- 微信与抖音真机低亮度下，玩家无需停顿即可区分相邻的 5 种沙色。
